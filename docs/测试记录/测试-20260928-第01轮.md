## 10. 结论与下一步

- **本轮是否可部署：否。** 3 个 P0 全在「教师配置评分 → 作用到学生」这条链路上，而这条链路正是本轮新改的部分。现状是：教师以为配好了，实际上①配置没落盘 ②配置没下发 ③保存动作还会反向篡改在线学生的换热器工况。对开课场景是致命的（教师配的初温 / 目标 SP 对学生一律无效）。
- **遗留 P0：**
  - D-P0-01 `snapshot-store-v2.js:setSettings` 落盘 `scoreConfig`
  - D-P0-02 `hxInitTempFromSettings()` 读不到配置时**不下发任何命令**（宁可不同步，也不能覆盖学生工况）
  - D-P0-03 评分配置按模型在学生会话建立时注入；或提供「下发到全部在线会话」的显式动作
- **下轮必做：**
  1. 修完 3 个 P0 后重跑本轮全部 L0~L2 + A/B 专项，断言"教师配 420 → 学生冷态 420、运行中 420"
  2. 补 G-05 / G-06 / G-07 / G-08 / G-10 五个 P0 缺口（`recovery/restore`、`stream`、名单 import、`teacher/clear`、限流 503）
  3. 修 D-P1-01（冷态可上传云端）与 D-P1-02（`mv=1/3` 的迁移或明确拒绝）
  4. D-P2-06：把回归基线按模型拆开写进 `可长期测试的稳定方案.md` §8.2
  5. 组织一轮真人 L5（学生 / 老师 / 运维各 1 人），特别是"重新登录后要手动再点启动"这条老疑点
  6. 装 git 或建立严格的整目录备份纪律 —— 本轮就出现"改了 `selftest_hx.cpp` 和两个 docs 却没进备份、无法 diff"
