--------------------------------------------------------------------------------
0. 结论摘要
--------------------------------------------------------------------------------

  可行。采用"双内核 + ModelSpec 驱动 + 模型维度隔离"的方案：

    - 三级液位内核 YunEngine     除新增 modelId 传参外，行为一行不改。
    - 新增换热器内核 YunEngineHX 独立进程、独立状态、独立历史。
    - 新增一个模型描述符 ModelSpec，把"哪些位号、哪几组曲线、哪些评分指标"
      等模型差异集中到数据，而不是散落到代码分支里。
    - 平台层（手操、回路卡、曲线、评分、保存、云端、教师监视与导出）
      只实现一份，全部读 ModelSpec。=> 换热器的功能不会比三级液位少，
      这是结构上保证的，不是靠人工对照维护的。
    - 教师端用开关决定开放哪些模型；默认只开液位，学生体验与现在完全一致。

  本方案的两条主线：
    主线 A  隔离：两个模型的数据与进程绝不互相读写（第 4 章）。
    主线 B  对等：所有功能只写一份，由 ModelSpec 决定模型差异（第 5、9-12 章）。

  必须先解决的 5 个硬约束（详见第 2、3 章）：
    1) 会话键缺少模型维度，同一学生两个模型会互相顶掉。
    2) 状态文件是裸 C++ 结构体 + YLV1 魔数，跨模型恢复等于读脏内存。
    3) 云端快照 meta 没有 modelId，且图片键写死 level/flow/valve。
    4) PID 口径两边不一致（本方案强制统一，见第 3 章）。
    5) 换热器 config.h 依赖 windows.h / gdiplus.h，在 Linux 容器里编译不过。

1. 目标与硬性约束
--------------------------------------------------------------------------------

1.1 目标
    - 学生在同一平台登录后，可使用三级液位或换热器实验。
    - 两种实验共用登录、班级、名单、手操、搭回路、曲线、评分、保存、云端、
      教师看板与导出的全部框架。
    - 教师可决定对当前班级开放哪些模型。

1.2 硬性约束（不可协商）
    C1  三级液位现有功能不得受影响：学生端、教师端、曲线、评分、云端上传/
        下载、导出、名单导入，全部必须继续正常工作。
    C2  两个模型必须完全隔离：状态、历史、曲线、评分、云端槽位、导出文件
        不得互相读写或覆盖。
    C3  液位的持久化键名、目录、文件魔数、历史字段名保持原值，以兼容
        已经产生的学生数据与云端方案。
    C4  换热器物理模型（能量守恒、LMTD、燃料->TI1103、阀门惯性）公式不改，
        只做工程化拆分（控制与物理分离、去掉 UI 依赖）。
    C5  PID 口径两边统一，见第 3 章。
    C6  功能对等（本版新增，最高优先级的功能性约束）：
        三级液位具备的功能，换热器一项都不能少。包括但不限于
        自由控制阀门（手操）、曲线全套交互、评分、保存与恢复、
        云端上传与下载、教师端实时监视与导出。
        实现方式不得是"给换热器再写一套"，必须是"同一份实现 + ModelSpec"。
    C7  两模型的差异只允许出现在三个地方：
        物理内核、P&ID 视图、ModelSpec 数据。
        任何出现在第四个地方的分支，都视为设计违规（见第 12 章）。

3. PID 口径统一（本方案强制项）
--------------------------------------------------------------------------------

3.1 决策
    两边统一采用 DCS 工业 PID 公式，积分增益直接定义 Ki = 1 / Ti：

        e(t)   = SP - PV
        P      = Kp * e(t)
        I      = (1 / Ti) * S e(t) dt
        D      = Kp * Td * d(e)/dt
        u(t)   = 偏置 + action * (P + I + D)

        action : +1 = 正作用, -1 = 反作用
        （S 表示对时间的积分）

    配套规则：
      - 积分项不含 Kp 因子，Ki 独立等于 1/Ti（单位 1/s）。
      - Ti 取无穷大（工程上以"无积分"档表示）时 I 才趋于 0；
        不允许用 Ti = 0 表示"无积分"，Ti = 0 为非法输入。
      - 微分项保留 Kp 因子，Kd = Kp * Td。
      - 微分先经低通滤波再求导，抑制测量噪声放大。
      - 输出限幅 0-100%，限幅时本次积分不提交（抗积分饱和）。

3.2 现状差异
    三级液位 native/pid.cpp：
        P = Kp * e
        I = PidKi(Ti) * (S e dt)，且 PidKi(Ti) = 1 / Ti
        D = Kp * Td * d(e)/dt
        => 与 3.1 完全一致，无需修改。

    换热器 model.cpp：
        温度环第 651 行  ki_eff = kp / Ti  => I = (Kp / Ti) * (S e dt)
        流量环第 319 行  fki_eff = kp / Ti => 同上
        => 换热器当前为 I = Kp/Ti 形式，与统一口径相差一个 Kp 倍。

3.3 移植时的处理
    (1) 换热器内核删除自带的积分/微分实现，改为调用与液位完全相同的
        PidStep()（编译期同一份 pid.cpp 源文件，不允许各自留副本）。
    (2) 换热器原有整定值 (Kp, Ti, Td) 是在 I = Kp/Ti 体系下调出来的，
        切换口径后必须重新整定，不能直接照搬。
    (3) test_scenarios.cpp 中依赖旧口径的数值断言需同步复标。
    (4) 自检增加一条跨内核一致性用例：给定同一组
        (Kp, Ti, Td, action, SP, PV, dt)，两内核的 P/I/D/u 必须逐位一致。

3.4 口径说明（供教学与评审核对）
    3.1 的形式属于"DCS 并联（独立增益）形式"：P、I、D 三个增益彼此独立
    —— Kp、Ki = 1/Ti、Kd = Kp*Td。它与"工业标准形 I = Kp/Ti"是两个不同的
    参数体系，整定值不可互换。本项目统一取并联形式，两边一致。

4. 隔离设计：六个边界
--------------------------------------------------------------------------------

    边界           三级液位（保持原值）              换热器（全部新增）
    ------------   -------------------------------   -----------------------------
    1 内核进程     YunEngine                          YunEngineHX
    2 会话键       classId::studentId（不改）         classId::studentId::hx
    3 运行态文件   data/runtime/（现有）              data/runtime/（前缀带模型）
    4 持久快照     data/state, history, submissions  data/hx-state, hx-history,
                                                      hx-submissions
    5 历史字段     HISTORY_FIELDS（不改）              HX_HISTORY_FIELDS
    6 模型描述符   MODEL_SPEC.tank（从现有常量提取）   MODEL_SPEC.hx

    硬规则：
      R1  液位的 sessionKey、目录名、magic("YLV1")、STATE_VERSION、
          HISTORY_FIELDS、快照文件键，全部保持原值，一个字节都不动。
      R2  任何快照在写入时记录 modelId；恢复前强校验，
          modelId 不匹配一律拒绝并提示，不做"猜测性兼容"。
      R3  换热器不得读写 data/state、data/history、data/submissions
          这三个液位目录。
      R4  模型选择走独立接口，禁止复用 SET_MODE。
      R5  ModelSpec 是数据，不是分支。平台层读到的是配置，
          不允许出现 if (modelId === 'hx') 这类散落判断（见第 12 章）。


--------------------------------------------------------------------------------
5. 目标架构：ModelSpec 驱动
--------------------------------------------------------------------------------

5.1 为什么必须是 ModelSpec
    v1.0 曾采用"给换热器新增独立视图、独立曲线组、独立评分细则"的写法。
    该写法有一个结构性缺陷：功能一旦分叉，就靠人工比对来维持一致，
    液位后续新增功能时换热器不会自动跟上，C6 永远无法保证。

    本版改为：所有功能只实现一份，模型差异收敛到一个描述符 ModelSpec。
    功能对等因此成为结构性质，而不是维护纪律。

5.2 架构图

    浏览器（学生端 / 教师端）
        |
        |  HTTP + SSE
        v
    Node 网关 server/server.js
        |-- 登录 / 班级 / Cookie / 教师账号        （完全复用，不改语义）
        |-- 模型注册表 models = { tank, hx }
        |-- sessionKeyForModel(classId, studentId, modelId)
        |       tank 仍用原 sessionKey（兼容旧数据）
        |-- 快照层 snapshot-store-v2               （加 modelId、目录分叉）
        |
        |-- spawn(YunEngine)     modelId = tank
        |-- spawn(YunEngineHX)   modelId = hx
        |
        +-- data/          液位持久化（原样）
        +-- data/hx-*/     换热器持久化（新增）

    前端
        |-- 通用组件层（只写一份）
        |     手操面板 / 回路卡 / 串级卡 / 参数卡 / PID 过程面板
        |     曲线组件（XY拖动、缩放、标注线、图例隐藏、SP线、清空、导出）
        |     仿真图容器（缩放、平移、全屏）
        |     评分面板 / 保存恢复面板 / 云端面板
        |     教师看板 / 监视 / 参数表 / 曲线查看器 / 导出
        |
        +-- 读 MODEL_SPEC[modelId] 决定：位号、曲线组、模板、评分指标、列头

    每个模型只实现三样独有物：
        物理内核 + P&ID 渲染器 + ModelSpec 数据

5.3 ModelSpec 字段定义（建议）

    {
      modelId       : "tank" | "hx"
      displayName   : 中文名
      enginePath    : 内核可执行文件路径
      stateMagic    : 状态文件魔数（"YLV1" / "YLHX"）
      historyFields : 历史字段数组
      curveGroups   : [ { key, label, series:[{key,label,color}], fixedYMax } ]
      pvCatalog     : [ { index, tag, unit } ]      回路卡"被控量"下拉
      mvCatalog     : [ { index, tag, unit } ]      回路卡"阀门"下拉
      manualTargets : [ { key, label, unit, min, max, disabledWhen } ]
                                                    手操面板（泵/阀/燃料）
      scoreMetrics  : 评分指标定义
      templates     : [ { key, label, command } ]    推荐 / 串级 / 高分 / 工况
      pidProcess    : PID 过程面板的字段映射
      exportColumns : 导出表头与列取值

    注意：tank 的 ModelSpec 必须由**现有常量提取**而成，取值与今天完全一致
    （位号数组、CURVE_DEFS、导出列头等）。提取是"搬家"，不是"改写"。

6. 换热器内核移植规格（YunEngineHX）
--------------------------------------------------------------------------------

6.1 目录（新增，与液位内核并列，互不引用）
    YunLevel/native-hx/
        hx-engine.cpp      stdin/stdout JSON 协议主体（参照 engine.cpp 结构）
        hx-model.h         BoilerSystem 的"纯物理"裁剪版
        hx-model.cpp       HxPlantStep() + InitScenario() + 场景自检
        hx-config.h        纯常量（从 config.h 剥离，不含任何 Windows 头）
        （pid.cpp / pid.h 复用上级 native/ 的同一份，不复制）
        （score 由平台侧评分框架按 ModelSpec.scoreMetrics 驱动）

6.2 拆分规则
    (1) 删除 BoilerSystem 中全部 history 数组与 data_count；
        历史统一由 Node 侧按 ModelSpec.historyFields 采集。
    (2) 把 UpdateSimulation() 拆成两个函数：
            HxControlStep(sys, dt)  仅 PID 计算，产出阀门指令，不推进物理
            HxPlantStep(sys, dt)    仅物理推进：阀门速率 -> 流量换算 ->
                                    燃料/炉膛/过热蒸汽动态 -> 能量守恒/LMTD ->
                                    金属壁温 -> 输出 PV
        调用顺序：HxControlStep -> HxPlantStep，与液位 RunControlStep 的位置
        保持一致，便于共用 TICK 语义。
    (3) 固定回路去硬编码：
        原 TIC1104->FV1103、FIC1105->FV1105 改为两条"模板回路"，
        通过 LOOP_ADD 的等价参数写入，物理步内不再出现 PV/MV 常量。
    (4) 类型与头文件清理：
        BOOL / TRUE / FALSE -> bool / true / false
        移除 windows.h、gdiplus.h、所有 pragma comment
        移除 UI 相关常量（控件 ID、BASE_W/BASE_H 等）
    (5) 位号定名（对应第 2.2 节 [L]）：
        统一定为 FV1102 = 除氧水（冷却）阀，FV1101 = 燃料阀，FV1105 = 出口阀；
        同步修正 ui/render/test 中的 FV1103 字样，并在文档中登记该决定。

6.3 移植验收
    - 在 Debian 容器内 g++ -std=c++17 -Wall -Wextra 零错误零警告编过。
    - 场景 A / 场景 B 的 InitScenario 初值与现有 test_scenarios 一致。
    - 物理公式与拆分前逐位一致（可用同一初始状态跑 N 步对拍）。

7. 接口与命令协议
--------------------------------------------------------------------------------

7.1 平台层
    POST /api/model/list        返回教师对本班开放的模型
    POST /api/model/select      学生选模型（或由登录响应直接决定）
    GET  /api/session/state     状态（按当前学生会话的 modelId 路由）
    其余 /api/* 接口语义不变，内部按 ModelSpec 分叉数据，不分叉逻辑。

7.2 内核命令（换热器与液位语义对齐，一一对应）
    通用运行：STATE / TICK n / START / PAUSE / DEACTIVATE / RESET
    手操    ：SET_PUMP / SET_VALVE i v / SET_BIAS
              （换热器对应 SET_VALVE 0/1/2 -> FV1101 / FV1102 / FV1105；
                若燃料走独立通道则另加 SET_FUEL，语义等价于 SET_VALVE）
    回路    ：SET_PID / SET_SP / SET_FLOW_SP / SET_PVX_SP
              LOOP_ADD / LOOP_DEL / LOOP_CLEAR
              CASC_ADD / CASC_DEL / CASC_CLEAR
    模板    ：TEMPLATE_A / TEMPLATE_B / PRESET / HIGH_SCORE
              （换热器：SCENARIO_A / SCENARIO_B 作为工况初值模板，
                建议直接并入 TEMPLATE_* 语义，避免另造命令族）
    评分    ：SCORE_MODE / SCORE_TANK / SCORE_START / SCORE_END
              （换热器的评分对象由 ModelSpec.scoreMetrics 决定，
                命令名与流程不变）
    其它    ：SAVE / QUIT
    明确禁止：用 SET_MODE 表示模型选择。

7.3 状态 JSON（换热器）
    字段名由 ModelSpec 声明，前端不写死：
        t, TI1103, TI1104, TI1104_sp, FI1105, FI1105_sp,
        FV1101, FV1102, FV1105, Q_hx, T_water_out,
        loops[], cascades[], score{}, mode, running, paused

7.4 手操规则（F-02 / F-03 的统一定义，两模型共用一套实现）
    - 手操目标来自 ModelSpec.manualTargets，前端按数组渲染，数量不限。
    - 液位：P101 + FV101~FV104（5 个）。
    - 换热器：FV1101 + FV1102 + FV1105（3 个，燃料若可手操则为 4 个）。
    - "应用手操"按钮：统一遍历当前所有可编辑目标，逐个下发命令；
      无回路时不可用的规则由后端返回的可编辑状态决定，不在前端另写判断。
    - 占用规则：某 MV 被任一回路/串级占用时，该手操控件禁用并显示回路值；
      该判断改为读取后端下发的 occupied 标记，两模型共用同一逻辑。

9. 曲线组件规格（两模型共用）
--------------------------------------------------------------------------------

  本章对应 2.3.2 的 F-20 ~ F-27。实现方式：一个通用曲线组件，
  按 ModelSpec.curveGroups 实例化；液位与换热器各实例一份，代码一份。

  9.1 分组与数据源
      F-20 曲线分组 tab：由 curveGroups 数组生成，组数不限。
           液位：level / flow / valve
           换热器：temperature / hxflow / valve
           历史字段由 ModelSpec.historyFields 决定，取数与液位同一套。

  9.2 视图交互
      F-21 XY 轴拖动 + 缩放
           复用现有 beginCurveInteraction / moveCurveInteraction /
           endCurveInteraction / clampCurveRange / curveFullRange 逻辑，
           状态按曲线组各自保存（现有 app.curve / app.teacherCurve 结构不变）。
      F-26 Y 轴上限可设
           由 ModelSpec 给出 fixedYMax 与"上限来源"。
           液位：流量组上限受阀门最大值约束（现有 normalizedFlowYMax）。
           换热器：温度组上限、流量组上限各自声明。

  9.3 标注线
      F-22 标注线：可显示/隐藏、可拖动、线上显示当前时间
           状态字段沿用 showAnnotation / annotationT。
           规则（两模型一致）：
             - 标注线不随光标移动，只能拖动；
             - 标注开关收起时，标注线一并消失；
             - 线上显示的时间可单独拖动，避免遮挡曲线。

  9.4 图例与曲线显隐
      F-23 点击图例位号隐藏/显示对应曲线
           图例项来自 curveGroups[].series，点击做取反（单按钮切换）。
      F-24 每个控制回路的 SP 线可区分、可显示/隐藏
           SP 线按回路实例生成（液位现有 sp1..sp3 与各回路 sp 轨迹），
           换热器的 SP 由 ModelSpec 声明；显隐状态与普通曲线同机制。

  9.5 清空与冷态语义
      F-25 清空曲线；曲线不受"回到冷态"影响
           复用 /api/curve-clear。冷态（RESET）只复位物理与回路，
           不清历史；该语义两模型一致，不得在换热器上另立规则。

  9.6 导出
      F-52 曲线 PNG 导出：exportCurvePng 通用化，
           文件名按 ModelSpec 与当前曲线组生成；
           教师端导出曲线图时带学生姓名（现有规则不变）。

11. 保存 / 恢复 / 云端规格

  本章对应 2.3.4 的 F-40 ~ F-45。四条线都必须按 modelId 分叉数据、

  11.1 当前态（F-40）

  11.2 工程槽位（F-41）

  11.3 恢复态（F-42）
      /api/student/auto-save 与 /api/recovery/restore
      强制退出（登出/断线）时自动保存，下次登录可选择恢复；
      恢复后回到"未启动"状态（现有约定不变），该约定两模型一致。

      恢复前校验 meta.modelId 与 state.bin 魔数，双重校验缺一不可。

  11.5 跨模型误恢复的处理
      当恢复目标与会话模型不一致时：
        拒绝恢复 -> 不修改当前会话任何状态 -> 返回明确错误码与提示文案。

20. 阶段 2 施工补充（2026-09-24 核对源码后补记）
--------------------------------------------------------------------------------

20.1 换热器侧现有 PID 口径（必须改）

    位置：Bolier2.1/model.cpp
      温度回路 第 646-664 行：ki_eff = (Ti > 0) ? (kp / Ti) : 0
      流量回路 第 306-329 行：fki_eff = (flow_Ti > 0) ? (flow_kp / flow_Ti) : 0
    即旧式 I 项 = (Kp / Ti) * ∫e dt，与液位侧 Ki = 1 / Ti 不一致；
    且旧式把 Ti = 0 当作"关闭积分"，液位侧 Ti = 0 是非法值、关闭积分用 Ti = ∞。
    移植时统一为：I 项 = (1 / Ti) * ∫e dt，Ti = ∞ 关闭积分，Ti = 0 直接拒绝。

20.2 整定值迁移换算（R-1 的量化缓解手段）

    旧：I_old = (Kp_old / Ti_old) * ∫e dt
    新：I_new = (1 / Ti_new) * ∫e dt
    若要复现旧积分强度：1 / Ti_new = Kp_old / Ti_old，即

        Ti_new = Ti_old / Kp_old

    含义：Kp 越大，同 Ti 下的积分作用相对旧式减弱越多，必须按此式回算；
    例如旧 Kp = 2.0 / Ti = 120 s，等强度新整定为 Ti_new = 60 s。
    比例项、微分项口径两侧一致，Kp 与 Td 可直接沿用，只有积分项换算。
    换算后仍需按第 3.3 节重新跑阶跃整定，本式只用于给出合理初值。

20.3 建议的移植顺序（先可跑，再对齐）

    1. 先原样移植物理内核（LMTD、能量守恒、阀门惯性、传感器延迟），保持数值可复现；
    2. 再替换 PID 为液位侧同款 PidStep（Ki = 1/Ti + 限幅抗积分饱和 + 手动无扰切换）；
    3. 换热器既有整定值按 20.2 换算后代入，跑场景 A/B 与液位侧对拍；
    4. 最后接入协议层（STATE / TICK / START / PAUSE / RESET / SET_* / LOOP_ADD / SET_PID / SAVE），
       与 native/engine.cpp 保持同名同语义命令，网关侧才能零分支复用。
