# 云仿真服务器部署说明（纯公网 IP 测试版）

本文档用于当前测试阶段：**不使用域名，不申请 HTTPS 证书，不做 ICP 备案**。
同学直接通过下面的地址访问：

```text
http://服务器公网IP:8080
```

正式长期开放时再考虑域名、HTTPS 和备案；本阶段只需要阿里云 ECS 的公网 IP 和放行 8080 端口。

> **接手人先看：**`docs/交接须知的注意文件.md` 是当前统一接手基线，包含双模型目录、
> 数据备份、线上部署命令和禁止操作。本文负责把 ECS 从零部署起来；实际更新版本时优先使用
> 根目录的 `deploy-yunlevel.ps1`，不要手工只覆盖某个前端文件。

> **重要：本文以 Ubuntu 22.04 LTS 为准。** 如果购买时选成了 Windows Server 2022，
> 建议在实例还没有业务数据时更换操作系统为 Ubuntu 22.04，再按本文部署。
> 当前云版按 Ubuntu + Docker 做过完整验证；直接在 Windows Server 上运行需要额外处理
> Node.js 安装、进程常驻、开机自启和文件上传，不适合作为第一次公网测试路线。

## 0. 确认 ECS 实例信息

在阿里云 ECS 控制台确认实例满足以下条件：

| 项目 | 本测试建议 |
| --- | --- |
| 规格 | `ecs.e-c1m2.large`（2 核 4 G） |
| 系统盘 | 40 GiB ESSD Entry |
| 操作系统 | Ubuntu 22.04 LTS 64 位 |
| 地域 | 华东 1（杭州）或其他离学校近的地域 |
| 公网 IP | **必须分配公网 IPv4** |
| 带宽 | 按使用流量计费，带宽峰值 5 Mbps |
| 登录方式 | 自定义 root 密码（本教程使用 root + 密码登录） |
| 安全组 | 先只放行 22，部署时再加 8080 |

> 免费流量要分清：华东 1（杭州）属于中国内地，免费试用页显示的 20 GB/月只适用于
> 这台上限；另外 200 GB/月是非中国内地地域的额度，杭州实例不能使用。20 GB 足够做
> 几次课堂测试，但请先在阿里云控制台设置流量告警，测试不用时执行 `docker compose down`。
>
> 如果账号里还有旧的 ECS 实例，新 Ubuntu 实例跑通后再停止或释放旧实例，避免两个实例
> 同时消耗试用资源或产生额外费用。
> 如果购买页面有“分配公网 IPv4”选项，必须勾选。没有公网 IP，同学无法从校园网或家里访问。
>
> 当前阶段不买域名、不买证书、不做备案。中国大陆地域的 ECS 用 `http://公网IP:8080`
> 做课堂测试即可。公网 IP 测试属于明文 HTTP，只适合临时测试，不要长期公开。

## 1. 配置安全组

进入 ECS 实例详情页，打开**安全组 → 配置规则 → 入方向**，添加：

| 端口范围 | 协议 | 授权对象 | 用途 |
| --- | --- | --- | --- |
| `22/22` | TCP | `0.0.0.0/0`（或你自己的出口 IP） | SSH 登录 |
| `8080/8080` | TCP | `0.0.0.0/0` | 学生通过公网 IP 访问 |

如果安全组里已经有 22，不要重复添加。测试时 22 也可以限制为“我的 IP”，更安全。

> 不需要开放 80 或 443。当前只用 8080。
>
> 如果实例上启用了 `ufw` 或 `firewalld`，除了安全组，还要在系统内放行 8080。

## 2. 登录服务器

在本机 PowerShell 或 Windows Terminal 执行：

```powershell
ssh root@你的服务器公网IP
```

第一次连接会提示确认指纹，输入 `yes`；然后输入购买时设置的 root 密码。

登录成功后，命令行提示符会变成类似：

```text
root@iZxxxxxxxxxxxxx:~#
```

## 3. 安装 Docker 和 Compose

如果创建实例时在“预装应用”里选择了 **Docker**，先登录服务器确认：

```sh
docker --version
docker compose version
```

两条命令都能输出版本号时，本节后面的安装命令可以跳过。若提示 `docker compose`
不存在，再按下面的步骤补齐。

在服务器上依次执行：

```sh
apt-get update
apt-get install -y ca-certificates curl gnupg
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  > /etc/apt/sources.list.d/docker.list

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

docker --version
docker compose version
```

两条版本命令都能输出版本号，说明安装成功。

如果 Docker 官方下载较慢，可以先在阿里云控制台为 ECS 配置公网访问，或在服务器上使用
阿里云容器镜像服务提供的 Docker 镜像加速地址。

### 可选：系统防火墙

如果使用 `ufw`，执行：

```sh
ufw allow 22/tcp
ufw allow 8080/tcp
ufw status
```

如果 `ufw status` 显示 `inactive`，说明系统防火墙没有启用，只需要阿里云安全组放行即可。

## 4. 上传 YunLevel

### 推荐方式：使用部署脚本

在**本机** PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目上级目录>\deploy-yunlevel.ps1"
```

脚本会自动打包、上传到 `/opt`、备份服务器 `/opt/YunLevel/data`、保留原有
`docker-compose.yml` 中的教师口令和数据挂载配置，然后执行 `docker compose up -d --build`。
脚本默认服务器为 `root@你的服务器公网IP`。

只想在本地生成发布包、不连接服务器时：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目上级目录>\deploy-yunlevel.ps1" -PackageOnly
```

### 手动上传方式（备用）

没有使用部署脚本时，才手工上传整个目录：

```powershell
scp -r <项目目录> root@你的服务器公网IP:/opt/YunLevel
```

上传过程中会要求输入 root 密码。上传完成后，可以再次 SSH 登录服务器确认：

```sh
ssh root@你的服务器公网IP
ls -la /opt/YunLevel
```

必须存在的文件或目录：

```text
native/
server/
public/
scripts/
Dockerfile
docker-compose.yml
package.json
```

`native/build/`、`data/`、`node_modules/` 不需要上传；Docker 构建时会重新编译 Linux 版内核。

如果服务器已存在旧目录，先停旧容器，再覆盖上传；不要删除 `/opt/YunLevel/data`，
否则学生状态、曲线和评分记录会被清空。

当前版本必须同时上传 `native/` 和 `native-hx/`，否则镜像里只会有一个内核。部署包由
`deploy-yunlevel.ps1 -PackageOnly` 生成时会自动排除本地 `native/build`、`native-hx/build` 和数据目录。

## 5. 设置总教师口令与班级名单

系统采用一个总教师账号，统一管理所有班级。首次上线只需要修改总教师口令：

```sh
cd /opt/YunLevel
vi docker-compose.yml
```

```yaml
YUN_CLASS_CODE: "你的班级码"       # 仅当 data/classes.json 不存在时生成首个空班级
YUN_TEACHER_CODE: "你的教师口令" # 总教师口令，所有班级共用
```

不要继续使用示例口令上线。教师登录后打开“班级管理”页面：

1. 新建班级，填写班级名称和班级码。
2. 逐个添加学生，或按“学号,姓名”每行一条批量导入。
3. 把班级码发给对应学生；学生不设密码，只填写班级码、学号和姓名登录。
4. 同一学号可以存在于不同班级，会话与状态按“班级 + 学号”隔离。

当前测试数据允许清空重建。清空前先备份整个 `/opt/YunLevel/data`，停止容器，再删除
`classes.json`、`state/`、`history/` 和 `score_records.jsonl`，最后重新启动。若只想重做名单，
直接在教师页覆盖导入即可，不需要删除运行数据。

当前是 HTTP 测试，`YUN_COOKIE_SECURE` 保持 `"0"`：

```yaml
YUN_COOKIE_SECURE: "0"
```

如果以后确定接入 HTTPS，再改成 `"1"`。

## 6. 构建并启动

本机已经准备好部署脚本。它在服务器上先备份 `/opt/YunLevel/data`，保留原有 `docker-compose.yml` 中的教师口令和数据挂载配置，再上传新版并重建容器：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目上级目录>\deploy-yunlevel.ps1"
```

脚本会两次提示输入服务器 SSH 密码：第一次上传安装包，第二次执行备份和部署。部署完成后会执行
`docker compose ps` 并输出容器状态。

在服务器的 `/opt/YunLevel` 目录执行：

```sh
cd /opt/YunLevel
docker compose up -d --build
```

第一次构建需要下载 Node 镜像并在容器内编译 C++ 内核，通常需要几分钟。

当前版本是双模型镜像，构建阶段必须同时生成两个内核：

```sh
docker compose exec yunlevel ls -lh /app/bin
```

输出中应同时存在 `YunEngine` 和 `HxEngine`。只看到其中一个时不要继续课堂使用，
应先重新执行 `docker compose up -d --build` 并检查日志。

查看状态和日志：

```sh
docker compose ps
docker compose logs --tail=100 yunlevel
```

看到类似下面的内容，说明服务已启动：

```text
YunLevel server listening on http://0.0.0.0:8080
```

在服务器本机验证：

```sh
curl http://127.0.0.1:8080/api/health
```

正常返回：

```json
{"ok":true,"online":0,"uptime":3,"engine":"YunEngine"}
```

## 7. 用公网 IP 验证

在服务器上先确认公网 IP：

```sh
curl -s https://checkip.amazonaws.com
```

输出应该和阿里云控制台里显示的**公网 IP**一致。然后在浏览器打开：

```text
http://你的服务器公网IP:8080
```

按下表逐项测试：

| 步骤 | 预期结果 |
| --- | --- |
| 打开首页 | 显示登录页，不是“无法访问”或超时 |
| 输入班级码、学号、姓名 | 名单匹配时能进入学生控制区 |
| 教师班级管理 | 能新建班级、导入名单、导出名单 |
| 登录页实验模型 | 三级液位和换热器均可选择；学生端换热器需教师先开放 |
| 教师模型筛选 | 可切换“全部模型 / 三级液位 / 换热器”，在线、云端和评分表均有模型列 |
| 冷态保存 | 未启动状态可直接点“保存当前状态”；运行中未暂停应提示先暂停 |
| 选择单回路高分模板 | 回路卡片正常显示，无报错 |
| 应用换热器推荐工况 | 生成 `TI1104 → FV1102` 单回路，并可启动 |
| 点击启动 | 仿真数据逐秒更新 |
| 打开曲线和 PID 计算过程 | 曲线、液位、流量、开度都能显示 |
| 开始评分 | 提示评分对象和方案，评分时间开始走 |
| 教师入口 | 用教师口令能查看在线学生和评分记录 |
| 导出模型名 | 评分 CSV、学生工程和云端 ZIP 文件名称包含“三级液位”“换热器”或“全部模型” |

如果学生和老师在不同的电脑、不同网络下都能用这个地址打开，公网 IP 测试部署就完成了。

## 8. 日常运维

在服务器上执行：

```sh
cd /opt/YunLevel

docker compose ps                 # 查看运行状态
docker compose logs --tail=200 yunlevel
docker compose restart            # 重启
docker compose down               # 停止并删除容器
docker compose up -d --build      # 更新代码后重建并启动
```

备份学生状态、曲线和评分记录：

```sh
cd /opt/YunLevel
tar -czf ~/yunlevel-data-$(date +%Y%m%d-%H%M%S).tar.gz data
ls -lh ~/yunlevel-data-*.tar.gz
```

完整备份数据、配置和两个模型的运行目录时，推荐使用项目交接文件中的完整备份命令；核心内容
至少应包含：

```text
/opt/YunLevel/data
/opt/YunLevel/data/hx-state
/opt/YunLevel/data/hx-history
/opt/YunLevel/docker-compose.yml
```

恢复备份：

```sh
cd /opt/YunLevel
docker compose down
tar -xzf ~/yunlevel-data-YYYYMMDD-HHMMSS.tar.gz
docker compose up -d
```

定期把备份文件下载到本机：

```powershell
scp root@你的服务器公网IP:/root/yunlevel-data-YYYYMMDD-HHMMSS.tar.gz "<项目上级目录>\backups\"
```

恢复前先再备份一次当前线上数据，并确认压缩包内容。不要把恢复命令写成删除 `data/` 后再解压。

测试结束后想省流量或省钱，可以停止并删除容器：

```sh
docker compose down
```

注意：`docker compose down` 只会停止网页和仿真服务，**不会停止阿里云 ECS 实例**。
ECS 仍在运行时，服务器的 vCPU、内存、云盘等资源仍可能继续计费或消耗免费试用额度。
如果要暂停云服务器，应在 ECS 控制台执行“停止”；优先选择“节省停机模式”，
但云盘、弹性公网 IP、快照等资源仍可能单独计费。需要彻底停止计费时应释放实例，
释放前先备份 `data/`。停止或重启后公网 IP 可能变化，学生端要使用新的地址。

需要继续使用时：

```sh
cd /opt/YunLevel
docker compose up -d
```

## 9. 常见问题

### 1. 浏览器打不开 `http://公网IP:8080`

按顺序检查：

```sh
# 服务器本机服务是否正常
curl http://127.0.0.1:8080/api/health

# 容器是否运行
cd /opt/YunLevel
docker compose ps

# 服务器是否监听 8080
ss -lntp | grep 8080
```

如果本机能返回 `{"ok":true...}`，但外部打不开，通常是阿里云安全组没有放行 `8080/8080`。
如果安全组已放行，再检查服务器上的 `ufw` 或 `firewalld`。

### 2. 提示 `engine exited`

查看内核是否存在：

```sh
cd /opt/YunLevel
docker compose exec yunlevel ls -l /app/bin
docker compose logs --tail=200 yunlevel
```

如果缺少 `YunEngine` 或 `HxEngine`，先在服务器确认：

```sh
docker compose exec yunlevel ls -lh /app/bin
```

缺少任意一个内核都重新构建：

```sh
docker compose up -d --build
```

换热器内核缺失或启动失败时，教师端的“换热器模型：开放”开关仍可能存在，但学生
进入换热器后会收到内核启动失败提示；这不是数据问题，重新构建双内核镜像即可。

### 3. 评分记录时间不对

容器默认可能使用 UTC。需要北京时间时，在 `docker-compose.yml` 的 `environment`
中加入：

```yaml
TZ: Asia/Shanghai
```

然后重启：

```sh
docker compose up -d
```

### 4. 同时在线人数达到上限

默认 `YUN_MAX_SESSIONS: "120"`。如果提示人数已满，可以根据内存情况调整：

```yaml
YUN_MAX_SESSIONS: "120"
```

2 核 4 G 在测试阶段建议不超过 60 人同时运行；人数增加前先检查内存：

```sh
free -h
docker stats
```

### 5. 公网流量跑得太快

当前按流量计费，学生每 1 秒收到一次状态推送。杭州实例免费额度是 20 GB/月，
建议创建两层预警：

1. **费用预算预警（推荐）**：在阿里云控制台顶部搜索“预算管理”，新建按月费用预算。
   预算额先设置一个很小的值，例如 10 元，并开启 50%、80%、100% 的邮件/短信通知。
   一旦流量超过免费额度产生费用，会先收到通知。
2. **流量/带宽报警**：在控制台搜索“云监控”，进入“报警服务 → 报警规则 →
   创建报警规则”，选择产品“云服务器 ECS”和实例 `iZbp...`，监控项选择
   “公网流出带宽”或“网络流出流量”（控制台名称可能随版本略有不同），
   例如带宽平均值超过 `4 Mbps` 连续 3 个周期时通知你。

另外，定期打开阿里云“免费试用”页面查看“公网流量”已用额度。测试结束后执行
`docker compose down`，可避免服务持续后台推送和消耗流量。

### 6. 想临时换公网 IP

ECS 的公网 IP 可能会变化；如果 IP 变了，学生用新的 `http://新公网IP:8080` 访问即可。
长期使用建议绑定弹性公网 IP，但当前测试阶段不是必需。

## 10. 以后正式使用时再做什么

当前测试版已经足够用公网 IP 上课。如果以后要长期公开使用，建议按下面的顺序升级：

1. 购买并解析域名。
2. 用 Caddy 反向代理到 `127.0.0.1:8080`，自动申请 HTTPS。
3. Caddy 配置中必须使用 `flush_interval -1`，否则 SSE 曲线更新可能被缓冲。
4. 把 `YUN_COOKIE_SECURE` 改成 `"1"`。
5. 中国内地服务器绑定域名并对外提供 80/443 时，完成 ICP 备案。
6. 安全组关闭对公网的 8080，只保留 80/443。

这些步骤不在当前“纯公网 IP 测试版”范围内。

## 11. 容量参考

| 同时在线 | 内存（约） | 出口带宽（约） | 建议配置 |
| --- | --- | --- | --- |
| 30 人 | 500 MB | 90 KB/s | 2 核 2 G |
| 60 人 | 1 GB | 180 KB/s | 2 核 4 G |
| 120 人 | 2 GB | 360 KB/s | 4 核 8 G |

系统为了减少流量，教师看板的更新时间最多每秒一次。每名学生对应一个独立的 C++ 仿真进程，
学生之间的回路、参数、曲线和评分不会相互影响。
