| 等级 | 数量 | 含义 |

## 二、P1 问题（建议优先看）

### 1. 「暂停」会被 TICK 强制解除（模型/协议）

**现象**：`PAUSE` 后 `state.paused=true`，但再发 `TICK 1`，`simTime` 仍 +1，且 **paused 被清掉**。

**代码依据**（`native/engine.cpp`）：

```text
cmd == "TICK" 且 run=1 时：
  sys.running = true;
  sys.paused = false;   // ← 直接清掉暂停
  UpdateSimulation(...);
```

**影响**：

- 服务器主循环用 `tick(running && !paused ? 1 : 0)`，UI 正常点「暂停」时服务端多半走 `TICK 0`，**界面上可能看起来暂停有效**。
- 但任何路径只要发出 `TICK 1`（调试、教师遥控、异常客户端），暂停会**静默失效**并继续仿真。
- 与界面「暂停」语义、与桌面版「暂停后不推进」不一致。

**学生/老师感受**：点了暂停曲线还在走，或“没点继续却在跑”。

---

### 2. 同班同学号重新登录后，旧 Cookie 仍可用（会话）

**现象**：`S001` 再次登录拿到新 `yun_token`，用**旧 token** 请求 `/api/me`、`/api/state` 仍为 **200**。

**影响**：文档写「后登录顶掉前一个」，实现上旧令牌未吊销 → 可能双端同时操作同一学生仿真，状态互相踩。

**老师感受**：在线列表/状态与学生实际不一致；课堂“只让一个终端有效”无法保证。

---

### 3. 搭建回路失败时 API 静默成功（体验/一致性）

**现象**：`LOOP_ADD 0 0` 后再 `LOOP_ADD 1 0`（抢同一阀）或重复搭建，HTTP 仍 **200 + ok**，`nLoop` 不变，**无 error 字段**。

**代码依据**：`LoopAdd` 返回负值时 **不置 state_changed，也不回错误**。

**影响**：

- 学生点「确认搭建」若前端只看 HTTP 成功，会以为建好了，其实没建。
- 教师远程排障时，命令“全绿”但拓扑没变。

**建议期望**：拒绝时返回明确错误（阀占用/重复/满 4 条），与界面弹层文案一致。

---

### 4. `SET_PID` 对 Ti=0 / 负数的语义与界面口径冲突（模型/安全）

| 输入 Ti | 引擎行为（`set_pid_value`） | 含义风险 |
|--------|---------------------------|----------|
| `0` | `clampd(ti, 1e-6, 1e9)` → **1e-6** | **积分极强**（Ki=1/Ti 极大），不是“关积分” |
| `<0` | `PID_TI_OFF`（∞） | 关积分（合法） |
| 界面 | 禁止 0 与负数 | 与 API/引擎不完全一致 |

**影响**：绕过 UI 时 Ti=0 会变成近乎无穷积分，仿真易顶死/异常，和教学口径「Ti=0 非法、关积分用 ∞」冲突。

---

### 5. 空跑 START 无任何过程引导（体验）

**现象**：不搭回路、泵=0 时 `START` 合法，长时间 `TICK` 液位一直 0，API/状态里没有「未建回路 / 泵未开 / 未投自动」类提示。

**影响**：新生第一分钟就卡死在“为什么不动”；教师答疑成本高。

（UI 或许有部分禁用逻辑，但模型/接口层不能阻止误操作，也缺少可展示的诊断字段。）

## 三、P2 问题（不好用 / 易误解）

### 6. `SCORE_START` 清空回路与泵阀

先点「高分模板」再点「开始评分」会**清空全部回路、泵阀回 0**。文档有写，但顺序反了就像“模板没用”。  
**建议**：开始评分后引导「请重新搭建或点高分模板」，或模板按钮在评分开始后高亮。

### 7. SP 可达域无预警

`SP=80/25/60` 且出口全开时，120 s 后液位约 `42.9/0/0`，与目标差很多。属物理可达域，但**无提示**，学生会以为 PID 坏了。

### 8. 命令协议对人不友好

- 动词必须大写：`LOOP_ADD` / `SET_VALVE` / `SET_SP 罐号 值`…
- 错名有时 `500 unknown command`，有时 `400 非法控制命令`
- `SET_SP 50 50 50` **不会**设三罐，会被解析成 `pv=50, v=50`（静默误解）

前端封装正确则无感；排障/脚本/教师遥控时容易踩坑。

### 9. 保存当前状态必须先暂停

`POST /api/current/save` → `400 请先暂停仿真，再保存当前状态`（文案清楚，属产品策略）。  
未暂停时导出 → `404 还没有保存当前状态`。功能可用，但**链路长**：暂停→保存→才能导出/上传。

### 10. 学生上传默认关闭

`POST /api/student/submit` → `403 教师尚未开放保存上传功能`。  
按设计开关合理，但学生端若只说失败、不说“等老师开放”，会当成功能坏了。

### 11. 教师名单导入格式敏感

- `rows: [["S010","钱十"]]` → `400 学号格式不正确：(空)`
- `rows: [{studentId,name}]` → 成功  

Excel 服务端解析与 API 形态不一致时，教师手写 JSON/异步导入易失败（UI Excel 路径需另验）。

## 五、课堂使用体验结论

| 场景 | 评价 |
|------|------|
| 老师备课/建班 | 基本可用；导入名单要注意格式；导出 CSV 目前很短（测试班几乎空） |
| 学生第一次实验 | **易卡**：空跑无提示、搭建失败无提示、SCORE_START 清配置 |
| 学生做评分 | 能计分；**必须先 SCORE_START 再搭线**，顺序反了像 bug |
| 老师盯课堂 | 总览/查看/遥控可用；**顶号与暂停**两处会让“现场状态”不可全信 |
| 排障/二次开发 | 命令协议与 Ti=0 语义危险，需严格按文档/前端封装 |

## 六、建议（仅建议，本次未改代码）

1. **TICK 1 不得清 `paused`**；仅在 `!paused` 时 `UpdateSimulation`。  
2. **重新登录时吊销同班同学号旧 token**（已有 `revokeStudentAuth`，确认登录路径是否调用）。  
3. **LOOP_ADD / SET_MODE 等失败返回业务错误码**，与 UI 文案一致。  
4. **Ti≤0 统一语义**：0 = 非法或 =∞，禁止 `1e-6` 这种“超级积分”。  
5. 状态里增加 `blockedReason` / 引导（未回路、泵=0、未自动、SP 不可达提示）。  
6. `SCORE_START` 后 toast：「配置已清空，请重新搭建或点高分模板」。  
7. 统一错误形态：非法命令一律 400 + 中文原因，避免 500 `unknown command`。

## 七、复现要点（便于你复测）

```text
# 1) 暂停被 TICK 打穿
PAUSE → 读 state.paused=true → TICK 1 → simTime+1 且 paused=false

# 2) 旧 Cookie
学生 S001 登录得 token1 → 再登录得 token2 → 仍用 token1 访问 /api/me

# 3) 搭建静默失败
LOOP_ADD 0 0 → LOOP_ADD 1 0（同阀）→ 仍 200，nLoop 不变

# 4) Ti=0
SET_PID loop 0 0.5 0 60 1 0 0 → 实际 Ti≈1e-6（极强积分）

# 5) SCORE_START 清配置
HIGH_SCORE → SCORE_START → loops/pump 清空
```

## 八、浏览器真实点选补充（Playwright，学生/教师）

截图目录：`%TEMP%\yun_ui_walk\`（`ui-conflict.png` / `ui-score.png` 等）

### 点选确认的问题

| 等级 | 现象 | 点选细节 |
|------|------|----------|
| **P1** | **搭建失败完全无提示** | 选 LI102→FV102（阀已被占）点「添加」：卡片数仍 1，**无 toast、无红字**；成功时才有「回路已添加」。学生无法知道为何没加上。 |
| **P1** | **学生看不到「高分模板 / 推荐工况」** | 两按钮 `teacher-only`。学生只能手搭；课堂统一进度困难，和文档「推荐工况」表述易误解为人人可用。 |
| **P1** | **冷态/未启动时不能「保存当前状态」** | 未启动时按钮禁用，title 仍是「请先暂停仿真，再保存当前状态」——冷态根本无法“先暂停”。未跑过仿真就无法存档。 |
| **P1** | **「开始评分」清空回路与泵** | 冷态点「系统评分→开始评分」后：回路区显示「暂未搭建回路」，泵输入回到 0。与 API 结论一致。 |
| **P2** | 运行中「回到冷态」禁用 | title「请先暂停仿真，再回到冷态」——逻辑合理，但若学生只点启动会卡住（需再点暂停）。 |
| **P2** | 回路卡标题顺序为「阀 → 液位」 | 显示 `单回路 1：FV102 → LI101`，与桌面版「LIC101→FV102」及「测→控」阅读习惯相反。 |
| **P2** | 评分页副标题滞后 | 已选「系统评分」后仍写「在控制区选择评分方案后开始评分」；开始后主标题「系统评分：进行中」正确。 |
| **P2** | 单回路搭建下拉可选流量 PV | `buildPv` 含 FI101–103；可添加成功（未报错）。是否应允许、如何整定，界面无说明。 |

### 点选确认正常的部分

- 学生登录后页签仅：控制/仿真、曲线、评分（教师看板/班级管理隐藏）— 权限 UI 正确  
- 错误班级码有文案「班级码不正确」  
- 成功添加回路：toast「回路已添加」；应用参数：「参数已应用」  
- 前馈偏置按钮 关↔开 切换正常  
- 运行中可看仿真数字、曲线 canvas  
- 教师登录后可见高分模板/推荐工况、教师看板、班级管理  

### 对课堂的含义

1. **第一节课**必须先讲「点添加没反应=失败」以及规则（阀独占）。  
2. **学生作业**若要求高分模板，应改由老师演示或放开该按钮。  
3. **存档/上传**只能在“运行后点过暂停”时做，课前准备态无法保存——流程要写进讲义。
